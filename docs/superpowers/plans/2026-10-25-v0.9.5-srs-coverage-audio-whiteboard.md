# Repetita v0.9.5 Implementation Plan: 100% SRS Coverage, Microphone Audio Recording & Playback, Anki Audio Interop, and Ephemeral Study Whiteboard

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Achieve 100% test coverage on all SRS scheduling engines and mathematical models; implement offline audio note recording in the card editor; provide automatic and manual audio playback with hotkey replay in the study session; support Anki `.apkg` audio packaging for import/export; and build an ephemeral drawing whiteboard overlay for active motor recall during study.

**Architecture:**
- **SRS Engine Coverage:** Exhaustive boundary and mutation unit tests for `FsrsEngine`, `Sm2Engine`, `FsrsParameters`, `StabilityCurveCalculator`, `FsrsOptimizerModels`, and `SrsScheduler` strategy providers.
- **Audio Pipeline:** `record` and `audioplayers` plugins wrapping platform-native microphones and audio sinks; integration with `MediaService` for SHA-256 deduplicated local media storage and standard `[sound:filename]` Anki tags.
- **Study Playback & Replay:** `AudioPlaybackService` managing audio session lifecycle with configurable autoplay on card display/flip and keyboard shortcut `R` replay on desktop.
- **Anki & Backup Interoperability:** Extraction of audio files from Anki `.apkg` zip archives via the `media` JSON index, and serialization of local audio assets back into exported `.apkg` archives.
- **Ephemeral Whiteboard:** Transparent `CustomPaint` drawing canvas layered atop `FlipCardView` supporting touch/pen gestures, stroke clearing, and auto-reset on card transition without database persistence.

**Tech Stack:** Dart 3, Flutter 3.13+, Drift SQLite, flutter_riverpod, audioplayers 6.8+, record 7.1+, Material 3.

**Spec:** [ROADMAP.md](file:///c:/Users/thoma/Documents/Projects/repetita/ROADMAP.md) (Milestones v0.9.5, §9.4 Audio nelle Carte, §15.1 Whiteboard in Studio).

## Global Constraints

- 100% offline-first: zero network calls, zero telemetry, zero external cloud dependencies.
- Privacy & security: audio files stored strictly in private app documents directory; zero microphone access outside explicit user recording.
- F-Droid compliant: zero proprietary libraries, zero Firebase / Google Play Services dependencies.
- Impeccable design: Material 3 styling with dark/AMOLED compatibility, zero pixel overflow on desktop or mobile.
- Ponytail efficiency: minimal overhead, ephemeral whiteboard memory cleanups on every card flip.
- Strict backwards compatibility: existing cards, tags, and reviews without audio must continue functioning seamlessly.

## Review Focus

1. **Microphone Permission & Error Handling**: Gracefully handle microphone permission denial on Android/iOS/desktop without app crashes or frozen UI state.
2. **Audio Player Cleanup**: Ensure `AudioPlayer` instances are immediately stopped and disposed when navigating away from `StudyScreen` or skipping cards.
3. **Whiteboard Gesture Isolation**: Drawing on the whiteboard must not trigger unwanted card flips, swipe gestures, or vertical list scrolls.
4. **Anki Sound Tag Compatibility**: Support both standard Anki `[sound:filename.mp3]` markup and `media://filename.mp3` references in card text.
5. **Database Migration Safety**: No breaking schema changes to Drift database; audio files are stored in the existing agnostic `Media` table.
